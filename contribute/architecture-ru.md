# Архитектура репозитория

[English](architecture.md) | [Русский](architecture-ru.md)

UIKit — единый публикуемый пакет `@gravity-ui/uikit`. В репозитории находятся исходный код пакета,
стили, документация, Storybook и тестовая инфраструктура; это не монорепозиторий приложений.
Потребители используют публичные точки входа пакета и никогда не импортируют код из `src/` этого
репозитория.

## Публичная поверхность пакета

Источник истины о публикуемых подпутях — `package.json`. Для каждой JavaScript-точки входа
собираются ESM- и CommonJS-версии с соответствующими декларациями TypeScript.

| Импорт потребителя                    | Исходная точка входа       | Стабильность и назначение                                                       |
| ------------------------------------- | -------------------------- | ------------------------------------------------------------------------------- |
| `@gravity-ui/uikit`                   | `src/index.ts`             | Стабильные компоненты, хуки, утилиты, конфигурация и типы                       |
| `@gravity-ui/uikit/toaster-singleton` | `src/toaster-singleton.ts` | Интеграция синглтона тостера                                                    |
| `@gravity-ui/uikit/i18n`              | `src/i18n/index.ts`        | I18n-утилиты и ресурсы                                                          |
| `@gravity-ui/uikit/server`            | `src/server.ts`            | Безопасные для сервера утилиты, сейчас — генератор корневого класса темы        |
| `@gravity-ui/uikit/legacy`            | `src/legacy.ts`            | Поверхность совместимости со старыми компонентами; не использовать в новом коде |
| `@gravity-ui/uikit/unstable`          | `src/unstable.ts`          | Экспериментальная поверхность без гарантий стабильной точки входа               |
| `@gravity-ui/uikit/styles/*`          | `styles/*`                 | Глобальные CSS/SCSS, шрифты, миксины и темы                                     |

Стабильный корневой barrel-файл реэкспортирует `src/components/index.ts`, `src/hooks/index.ts`, а
также выбранные утилиты и типы. У папок компонентов и хуков есть собственные `index.ts`. Новый
публичный символ нужно намеренно провести через всю эту цепочку экспортов; сам факт наличия файла
в `src/` не делает его публичным.

Граница зрелости — часть API-контракта:

- в прикладном коде предпочитайте стабильную корневую точку входа;
- оставляйте API только для совместимости в `legacy` и не расширяйте их использование;
- публикуйте API в разработке через `unstable`, обычно с префиксом `unstable_`;
- не добавляйте зависящие от браузера API в серверную точку входа.

## Организация исходного кода

### Компоненты

Продакшен-компоненты находятся в `src/components/<Component>/`. Обычно рядом лежат реализация
(`<Component>.tsx`), стили (`<Component>.scss`), публичный barrel (`index.ts`), README, юнит- и
визуальные тесты, stories и i18n-ресурсы. В больших компонентах могут быть внутренние папки
`components/`, `hooks/` и `utils/`, но это не делает их содержимое публичным.

Общие семейства компонентов и уровни зрелости тоже находятся в `src/components/`:

- `controls/`, `layout/`, `mobile/`, `tabs/` и `theme/` предоставляют сгруппированные стабильные API;
- `legacy/` поддерживает старую точку входа;
- `lab/`, `TreeList`, `TreeSelect` и `useList` содержат API, выборочно публикуемые через unstable;
- в `utils/` лежит реализация, общая для нескольких компонентов.

### Хуки и утилиты

Публичные переиспользуемые хуки лежат в `src/hooks/` и экспортируются через `src/hooks/index.ts`.
Приватные и lab-хуки остаются в соответствующих подпапках до намеренного перевода в публичный API.
Общие утилиты находятся в `src/utils/`, а утилиты уровня компонентов — в `src/components/utils/`.

### Стили и темы

`styles/styles.scss` — глобальная точка входа стилей, а `styles/fonts.scss` настраивает поставляемые
шрифты. Определения тем находятся в `styles/themes/`: общие структурные токены — в
`styles/themes/common/`, наборы цветов — в `light`, `dark`, `light-hc` и `dark-hc`.

Компоненты используют CSS-переменные и SCSS рядом с реализацией. В прикладных стилях следует
использовать семантические цветовые токены `--g-color-base-*`, `--g-color-text-*` и
`--g-color-line-*`; `--g-color-private-*` — внутренний слой палитры. Зависящие от направления стили
используют логические свойства, чтобы компонент одинаково работал в LTR и RTL.

### Интернационализация

Глобальная настройка языка начинается в `src/utils/configure.ts`; публичная точка входа i18n —
`src/i18n/index.ts`. Компоненты со встроенным текстом хранят JSON локалей и подключающий код в
своих папках `i18n/`. Добавляйте встроенный пользовательский текст через этот механизм, а не
зашивайте один язык в код компонента.

## Сборка и публикуемые артефакты

`gulpfile.js` управляет сборкой пакета:

1. очищает сгенерированные файлы;
2. компилирует TypeScript и декларации в `build/esm` и `build/cjs`;
3. копирует JSON локалей в оба дерева модулей;
4. компилирует глобальные стили и SCSS компонентов;
5. генерирует документацию компонентов для пакета.

ESM-вывод объявляет `type: module`, CommonJS-вывод — `type: commonjs`. Публикуются только `build/`
и `styles/`. `package.json` направляет `import` и `require` в соответствующие деревья, поэтому
изменения точки входа должны быть симметричны для кода и типов.

## Документация и примеры

Руководства по использованию пакета находятся в `docs/`; внутренняя документация для
контрибьюторов, включая это архитектурное руководство, — в `contribute/`. Описание API и поведения
конкретного компонента лежит в README рядом с его кодом. Stories компонентов находятся в
`src/components/<Component>/__stories__/`, а общие истории про брендинг, цвета, типографику и
витрины — в `src/stories/`. Конфигурация Storybook лежит в `.storybook/` и обеспечивает
интерактивную документацию и проверки доступности.

## Тесты и проверки качества

- Jest находит `*.test.ts` и `*.test.tsx`, обычно в соседних папках `__tests__/`, используя
  `jest.config.js` и общую настройку из `test-utils/`.
- Компонентные тесты Playwright находят `__tests__/*.visual.test.tsx` под `src/` через
  `playwright/playwright.config.ts`; snapshots хранятся рядом с компонентом в `__snapshots__/`.
- Для Storybook есть статическая сборка и отдельный браузерный test runner в `.storybook/`.
- ESLint, Stylelint, Prettier и TypeScript проверяют соответственно код, SCSS, Markdown и типы.

Выбирайте минимальный подходящий цикл по [навигации](navigation-ru.md), но запускайте полные проверки
пакета при изменении публичных barrel-файлов, конфигурации сборки, общей инфраструктуры или
публикуемых артефактов.
