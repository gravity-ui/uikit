# Навигация по репозиторию

[English](navigation.md) | [Русский](navigation-ru.md)

Используйте эту страницу как индекс для работы контрибьютора с репозиторием. Сначала читайте
авторитетную документацию, затем открывайте только указанный участок исходного кода и завершайте
подходящей проверкой. [Архитектурное руководство](architecture-ru.md) определяет границы пакета и
уровни зрелости, общие для всех маршрутов.

## Ориентиры в исходном коде

- `src/components/` — компоненты, их семейства и документация, тесты, stories и стили рядом с кодом.
- `src/hooks/` — публичные, приватные и экспериментальные React-хуки.
- `src/utils/` и `src/components/utils/` — общие и компонентные утилиты.
- `styles/` — публикуемые глобальные стили, шрифты, миксины, токены и встроенные темы.
- `src/stories/` и `.storybook/` — общие stories и конфигурация Storybook.
- `test-utils/`, `jest.config.js` и `playwright/` — инфраструктура юнит- и визуальных тестов.
- `gulpfile.js` и `package.json` — сборочный процесс и публичный контракт пакета.

## Проверки с учётом типа изменений

Для каждого изменения начинайте с минимального быстрого цикла, который его покрывает, и доводите
все применимые обязательные проверки до зелёного состояния. Всегда запускайте `git diff --check`.

Предпочитайте npm-скрипты из `package.json` как точки входа для валидации: благодаря им локальная
проверка совпадает с CI. Для быстрого целевого цикла передавайте этим скриптам пути к файлам или
поддерживаемые параметры, например `npm run lint:js -- <files>` или `npm test -- <test-files>`.
Также можно напрямую запускать специальные инструменты репозитория, для которых есть собственное
руководство по запуску. Не создавайте одноразовые валидаторы; если нужную проверку не покрывает
скрипт пакета или документированный инструмент, сообщите о пробеле в валидации.

- Markdown: `npm run lint:prettier`.
- TS/TSX: `npm run lint:js -- <changed-files>`, `npm run typecheck` и
  `npm test -- <exact-test-files>`. Используйте `--findRelatedTests` только для действительно общего
  кода: базовый компонент может запустить почти весь набор тестов.
- SCSS или визуальное поведение: `npm run lint:styles` и целевой файл Playwright.
- Публичные экспорты, общая инфраструктура или конфигурация пакета/сборки: полные
  `npm run lint`, `npm run typecheck`, `npm test` и `npm run build`.
- Storybook и его конфигурация: `npm run build-storybook`; запускайте `test-storybook`, только если
  доступен локальный или удалённый Storybook target.

Если зависимости отсутствуют или не согласованы, восстановите их через `npm ci`, прежде чем
объявлять ошибку проверки проблемой baseline. Нельзя считать работу завершённой, пока обязательная
проверка остаётся красной.

Обновление snapshots — явное исключение: запросите отдельное разрешение, после него обновите только
релевантные snapshots, повторите целевой Playwright-тест и перечислите каждый изменённый snapshot.
